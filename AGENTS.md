# Конвенции проекта mm-standx

Маркет-мейкинг бот для StandX Community Maker Yield.

| Документ | Что внутри |
| --- | --- |
| [PLAN.md](./PLAN.md) | Стратегия, экономика, архитектура, дорожная карта. **§0 — текущее состояние**, §13 — журнал находок, §14 — принятые решения |
| [docs/standx-api.md](./docs/standx-api.md) | Спецификация внешнего API с поправками, найденными на живом счёте |
| [docs/setup.md](./docs/setup.md) | Подключение счёта: депозит, перевод в Perps Wallet, ключи |

**Язык интерфейсов — только английский**, см. `.cursor/rules/english-only.mdc`.
Правило распространяется на всё, что программа выводит: ошибки, логи, вывод CLI,
сообщения валидации, имена тестов. Комментарии временно исключены.

## Архитектура

Гексагональная. Зависимости направлены строго внутрь:

```
cmd → app → ports ← adapters
        ↓
      domain          (не зависит ни от чего)
```

| Слой | Правило |
| --- | --- |
| `internal/domain` | Чистый. Ни I/O, ни `time.Now()`, ни сети, ни глобального состояния. Только stdlib и `decimal`. |
| `internal/ports` | Только объявления интерфейсов и DTO. Никакой логики. |
| `internal/app` | Оркестрация. Зависит от `ports` и `domain`, **никогда** от `adapters`. |
| `internal/adapters` | Реализации портов. Могут зависеть от `domain` для маппинга. |
| `cmd` | Композиционный корень. Единственное место, где адаптеры связываются с портами. |

Нарушение направления зависимостей — это баг, а не стилистическое замечание.

## Деньги и числа

- **`float64` для цен, количеств и денег запрещён.** Только `decimal.Decimal`
  (`internal/domain/money`).
- `float64` допустим ровно для двух вещей: пороги в базисных пунктах (`money.Bps`)
  и значения метрик. Цена ордера при этом всегда вычисляется в `decimal` и снэпается к тику.
- Любая цена, уходящая на биржу, проходит через `SymbolSpec.SnapPrice`, любое
  количество — через `SymbolSpec.SnapQty`.

## Событийная модель

- `internal/events` — типизированная синхронная in-process шина.
- **Контракт: обработчик не имеет права блокироваться.** Долгая работа — через
  собственную очередь подписчика (актор кладёт событие в свой inbox и возвращается).
- Синхронная доставка выбрана намеренно: тесты получаются детерминированными,
  скрытых горутин нет.
- Публикация только доменных фактов в прошедшем времени (`MarkPriceUpdated`,
  `OrderFilled`), не команд.

## Конкурентность

- Одна горутина-актор на символ владеет всем своим состоянием. Мьютексов в `app` нет.
- Общее изменяемое состояние между акторами запрещено — только сообщения.
- Ядро решения — чистая функция `Decide(State, Event) → (State, []Command)`.
  Ни времени, ни случайности внутри: всё приходит в событии.

## DI

- `uber-go/fx`. Модуль на пакет: `fx.Module("standx.rest", fx.Provide(...))`.
- Конструкторы принимают и возвращают **интерфейсы** из `ports`, не структуры адаптеров.
- Ресурсы с жизненным циклом (WS-соединения, HTTP-серверы, акторы) регистрируются
  через `fx.Lifecycle` с `OnStart`/`OnStop`. Никаких `go func()` в конструкторах.

## Время

- Никаких прямых `time.Now()`, `time.Sleep`, `time.After` вне адаптеров.
  Только порт `ports.Clock` — иначе тесты становятся медленными и флаки.

## Ошибки

- Оборачивать с контекстом: `fmt.Errorf("place order %s: %w", id, err)`.
- Сигнальные ошибки — через `errors.Is`/`errors.As`, не сравнением строк.
- В горячем пути ошибка не глотается: либо обработана, либо опубликована
  как событие, либо поднята в супервизор.

## Безопасность

- Приватные ключи только из переменных окружения, никогда из файлов конфигурации.
- Ключи и JWT не попадают в логи. Тип `Secret` с `String() → "[REDACTED]"`.
- Любой путь, отправляющий ордер, обязан проверять `runtime.mode == live`;
  в `dry_run` команда логируется и публикуется как событие, но не уходит на биржу.

## Тесты

- `internal/domain` — property-based (`pgregory.net/rapid`), инварианты из PLAN.md §7.1.
- `internal/adapters/fake` — симулятор StandX на том же проводном протоколе;
  интеграционные тесты гоняют бот без изменений против него.
- Тесты с реальными ордерами — build tag `live`, требуют `STANDX_LIVE=1`.
- Криптография (подписи) обязана иметь фиксированные тест-векторы.

## Команды

```bash
make build      # сборка всех бинарников в ./bin
make test       # unit + property тесты
make test-int   # интеграционные против fake-биржи
make test-live  # дымовой тест с реальными ордерами (нужен STANDX_LIVE=1)
make lint       # go vet + staticcheck
make record     # запуск cmd/recorder для сбора рыночных данных
```
