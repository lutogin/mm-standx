## Где проект находится сейчас

Контур собран и проверен: 261 тест, дымовой тест на живом счёте прошёл
на золоте (девять сценариев, 2 цента). Инструмент выбран — **XAU-USD**,
по глубине стакана внутри полосы награды.

**Бот ни разу не работал в боевом режиме.** Всё измеренное получено в теневом,
где заглушка принимает любую заявку.

Решение о запуске упирается в одно число: **фактическая ставка пула должна
превышать 22 USD за Maker Hour**. Она не публикуется и с нашей стороны
не вычислима — берётся из интерфейса биржи после первого дня работы.
Подробности и вывод порога — в §0 PLAN.md.

**Язык — только английский**, см. `.cursor/rules/english-only.mdc`. Правило
распространяется на всё, что программа выводит: ошибки, логи, вывод CLI,
сообщения валидации, имена тестов, — **и на комментарии в коде тоже**.

Существующие русские комментарии остаются как есть и не переводятся: правка ради
языка засоряет историю и не даёт ничего, кроме конфликтов при слиянии. Но всякий
новый комментарий пишется по-английски, включая комментарии в `config/config.yaml`
и `.env.example`. Кодовая база сходится к одному языку по мере того, как код
переписывается по существу.

## Архитектура

Гексагональная. Зависимости направлены строго внутрь:

```
cmd → app → ports ← adapters
        ↓
      domain          (не зависит ни от чего)
```

| Слой | Правило |
| --- | --- |
| `internal/domain` | Чистый. Ни I/O, ни `time.Now()`, ни сети, ни глобального состояния. Только stdlib и `decimal`. |
| `internal/ports` | Только объявления интерфейсов и DTO. Никакой логики. |
| `internal/app` | Оркестрация. Зависит от `ports` и `domain`, **никогда** от `adapters`. |
| `internal/adapters` | Реализации портов. Могут зависеть от `domain` для маппинга. |
| `cmd` | Композиционный корень. Единственное место, где адаптеры связываются с портами. |

Нарушение направления зависимостей — это баг, а не стилистическое замечание.

## Деньги и числа

- **`float64` для цен, количеств и денег запрещён.** Только `decimal.Decimal`
  (`internal/domain/money`).
- `float64` допустим ровно для двух вещей: пороги в базисных пунктах (`money.Bps`)
  и значения метрик. Цена ордера при этом всегда вычисляется в `decimal` и снэпается к тику.
- Любая цена, уходящая на биржу, проходит через `SymbolSpec.SnapPrice`, любое
  количество — через `SymbolSpec.SnapQty`.

## Событийная модель

- `internal/events` — типизированная синхронная in-process шина.
- **Контракт: обработчик не имеет права блокироваться.** Долгая работа — через
  собственную очередь подписчика (актор кладёт событие в свой inbox и возвращается).
- Синхронная доставка выбрана намеренно: тесты получаются детерминированными,
  скрытых горутин нет.
- Публикация только доменных фактов в прошедшем времени (`MarkPriceUpdated`,
  `OrderFilled`), не команд.

## Конкурентность

- Одна горутина-актор на символ владеет всем своим состоянием. Мьютексов в `app` нет.
- Общее изменяемое состояние между акторами запрещено — только сообщения.
- Ядро решения — чистая функция `Decide(State, Event) → (State, []Command)`.
  Ни времени, ни случайности внутри: всё приходит в событии.

## DI

- `uber-go/fx`. Модуль на пакет: `fx.Module("standx.rest", fx.Provide(...))`.
- Конструкторы принимают и возвращают **интерфейсы** из `ports`, не структуры адаптеров.
- Ресурсы с жизненным циклом (WS-соединения, HTTP-серверы, акторы) регистрируются
  через `fx.Lifecycle` с `OnStart`/`OnStop`. Никаких `go func()` в конструкторах.

## Время

- Никаких прямых `time.Now()`, `time.Sleep`, `time.After` вне адаптеров.
  Только порт `ports.Clock` — иначе тесты становятся медленными и флаки.

## Ошибки

- Оборачивать с контекстом: `fmt.Errorf("place order %s: %w", id, err)`.
- Сигнальные ошибки — через `errors.Is`/`errors.As`, не сравнением строк.
- В горячем пути ошибка не глотается: либо обработана, либо опубликована
  как событие, либо поднята в супервизор.

## Безопасность

- Приватные ключи только из переменных окружения, никогда из файлов конфигурации.
- Ключи и JWT не попадают в логи. Тип `Secret` с `String() → "[REDACTED]"`.
- Любой путь, отправляющий ордер, обязан проверять `runtime.mode == live`;
  в `dry_run` команда логируется и публикуется как событие, но не уходит на биржу.

## Тесты

- `internal/domain` — property-based (`pgregory.net/rapid`), инварианты из PLAN.md §7.1.
- `internal/adapters/fake` — симулятор StandX на том же проводном протоколе;
  интеграционные тесты гоняют бот без изменений против него.
- Тесты с реальными ордерами — build tag `live`, требуют `STANDX_LIVE=1`.
- Криптография (подписи) обязана иметь фиксированные тест-векторы.

## Конфигурация

Два слоя по возрастанию приоритета: **умолчания кода → YAML-файл**. Окружение
не переопределяет ничего.

- **`config/config.yaml`** — единственный файл конфигурации в репозитории
  и единственный источник настроек: инструменты, аллокация, лимиты риска,
  аппетит, оценщик волатильности, параметры начисления. Версионируется,
  объясняется комментариями, **в образ не запекается** — едет на сервер
  отдельно и подключается томом.
- **Окружение** — ровно две переменные, и обе не про стратегию:
  - `STANDX_WALLET_PK` — приватный ключ. Помечен `koanf:"-"`; попытка задать
    его в YAML роняет загрузку.
  - `MM_MODE` — `dry_run` | `live`. В файле не принимается намеренно: файл
    одинаков везде, где его запускают, а строка `mode: live` в нём означала бы,
    что любой локальный прогон на машине с рабочим ключом отправляет настоящие
    ордера. Незаданная переменная означает `dry_run`; неизвестное значение —
    отказ загрузки, а не молчаливый теневой режим.
- Неизвестный ключ роняет загрузку с указанием имени, а не игнорируется молча.
- Инструменты отбираются флагами `enabled` в блоке `symbols`. Второго способа
  сказать то же самое нет.

Слоя `MMSTANDX_*` больше не существует, и снят он по цене двух происшествий.
11 августа устаревший ключ `reference`, оставшийся в `.env` от закрытой ветки,
уронил процесс в цикл падения: деплой на упавший старт откатывается на прошлый
образ, то есть одна забытая строка тихо заморозила прод на старой сборке.
Второй случай тише и дороже — действующие пределы риска разъехались с файлом,
и по числам в репозитории нельзя было сказать, чем торгует бот: аллокация
стояла 1000 против 60 в файле, ориентир был выключен вопреки нему.

Оставшаяся на сервере переменная `MMSTANDX_*` теперь не делает ничего,
но процесс называет её при старте отдельной строкой лога (`StaleEnvOverrides`):
разница между «параметр задан» и «параметр действует» обязана быть слышна.

Действующие значения по-прежнему можно спросить у работающего процесса:

```bash
curl -s localhost:9090/metrics | grep mm_risk_limit
```

Убирать секцию `risk` из файла бессмысленно: при её отсутствии значения
возьмутся из `internal/config/defaults.go`, то есть из скомпилированного кода —
запечены сильнее, а прочитать их на сервере уже нельзя.

## Развёртывание

Образ содержит только бинари. Конфигурация едет отдельно: CI копирует каталог
`config/` и `docker-compose.yml` на сервер перед выкаткой. Руками там живёт
единственный файл — `.env` с ключом кошелька и `MM_MODE`.

```bash
make image && make push                      # машина разработки

mkdir -p data logs && chown 10001:10001 data logs   # сервер, один раз
docker compose pull && docker compose up -d
```

`logs/` деплой создаёт и сам, но создать его до первого `up` всё равно нужно:
отсутствующий источник bind-mount Docker заводит от root, и процесс под uid
10001 в него не пишет. Отказ тихий — бот работает с одним stdout.

Правка порога на сервере не требует сборки: файл смонтирован.

```bash
vim /root/opt/mm-standx/config/config.yaml
docker compose --project-directory /root/opt/mm-standx restart mmbot
```

Такая правка живёт до следующего деплоя — CI кладёт версию из репозитория.
Изменение, которое должно её пережить, коммитится.

Откат снимает пару целиком, образ и конфигурацию: перед подменой деплой
сохраняет действующий каталог в `config.previous/`. Старый бинарь с новым
файлом — такое же несочетание, как наоборот.

Каталог `data/` лежит рядом с `docker-compose.yml` — статистика забирается
обычным `scp`, без `docker cp`. Он обязан принадлежать пользователю контейнера
(uid 10001), иначе процесс не сможет писать и упадёт на старте.

Значения в `.env` **без кавычек**: `docker compose` их снимает,
а `docker run --env-file` передаёт дословно, и ключ кошелька перестаёт
разбираться.

`pull` обязателен: с тегом `:latest` один `up -d` поднимет уже скачанный образ.

**Монтируется каталог `config/`, а не файл.** Одиночный файл Docker привязывает
по иноду: правка через `vim` или `sed -i` создаёт новый инод, и контейнер
продолжает видеть старое содержимое, ничего об этом не сообщая. Вторая ловушка
там же — при отсутствии файла Docker создаёт на его месте пустой каталог,
и процесс падает на «is a directory» только на той машине, где файла нет.

Сторожа в Docker нет: он обнаруживает лишь смерть процесса, а это закрывает
`restart` плюс сверка при старте. Вне Docker сторож нужен.

## Наблюдаемость

| Что нужно | Откуда | Объём |
| --- | --- | --- |
| Состояние сейчас | `curl localhost:9090/metrics` | — |
| Чем питаются пороги опасности | `fast_signal` в строке `engine status`, `mm_reference_staleness_seconds` | — |
| Поза по календарю публикаций | `news` в строке `engine status`, `mm_withdrawals_total{cause="news_*"}` | — |
| Прямо сейчас | `data/stats/current.json` — незавершённый час, обновляется раз в 10 мин | — |
| История по часам | `data/stats/hourly-*.ndjson`, забирается `scp` | 110 КБ/сутки |
| Разбор инцидента | `logs/mmbot.log` рядом с `docker-compose.yml`, забирается `scp`; то же самое в `docker logs mmbot` | ~20 МБ/сутки, на диске до 550 МБ |

Почасовая свёртка пишется процессом сама: мгновенные величины сворачиваются
в квантили, счётчики — в разность за час. Час выбран потому, что биржа считает
начисление по календарным часам UTC.

**Инвариант: признак жизни производит актор, а не наблюдатель.** Отметка
ставится первой строкой `Engine.onTick` (`app/liveness.Beacon`); файл биения
и `/healthz` её только читают. Молчание актора дольше пяти секунд замораживает
файл — сторож снимает котировки — и переводит `/healthz` в 503, отчего
контейнер становится `unhealthy`. Второе важнее первого в боевой поставке:
сторожа в Docker нет. Обратный порядок — наблюдатель со своим таймером —
13 августа дал `healthy` при мёртвой торговле на тридцать пять минут.

**Инвариант: быстрый поток не занимает очередь актора.** Стакан и внешний
ориентир кладутся в ячейку на одно значение (`bookIn`/`referenceIn`) плюс
будилка ёмкостью один; очередь остаётся событиям о собственных ордерах,
исполнениях и позиции. Устаревший снимок стакана не нужен никому, а потерянное
исполнение восстанавливается только сверкой — в одной очереди первое вытесняет
второе под нагрузкой, что и случилось 13 августа. Правило закреплено тестом
на AST (`engine/architecture_test.go`), потому что ломается оно правкой,
выглядящей как приведение к единообразию.

**Инвариант: неработающий актор обязан объясняться.** Ни один выход из
`Engine.evaluate` не имеет права быть молчаливым — каждый проходит через
`reportBlocked`, и строка `engine status` раз в 15 секунд несёт либо геометрию
котировки, либо `quoting=no` с причиной. Молчание в логе означает смерть
процесса и ничего больше; ноль в `mm_quoting` без строки с причиной — это баг
наблюдаемости, а не наблюдение.

Разбор «бот перестал выставлять ордера» начинается с одной команды:

```bash
docker logs --since 20m mmbot 2>&1 | grep 'engine status' | tail -3
```

**Останавливающих защёлок в контуре ровно одна** — дневной убыток. Она
персистится в `data/state/risk-ledger.json`, переживает перезапуск намеренно
и снимается сменой суток UTC или удалением файла. Всё остальное, что
приостанавливает котирование, выражено сроком и снимается само:
частота заливов (`Verdict.PausedUntil`), серия заливов (`fillBurstUntil`),
пауза после залива (`cooldownUntil`). Заводя новое ограничение, проверьте, к
какому из двух классов оно относится: транзиентное условие, получившее
постоянный ответ, — это зависание, а не защита.

## Команды

```bash
make build      # сборка всех бинарников в ./bin
make test       # unit + property тесты
make test-live  # дымовой тест с реальными ордерами (нужен STANDX_LIVE=1)
make lint       # go vet + staticcheck
make image      # Docker-образ, только бинари
make push       # публикация образа в реестр
make record     # запуск cmd/recorder для сбора рыночных данных
```

`make run` берёт режим из `MM_MODE`. Теневой прогон на машине с боевым `.env`:
`make run MM_MODE=dry_run` — переменная командной строки сильнее файла.

`STANDX_LIVE=1` относится **только к дымовому тесту**. Боевой режим самого бота
включается единственной ручкой — `MM_MODE=live`.
