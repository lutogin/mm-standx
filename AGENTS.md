## Где проект находится сейчас

Контур собран и проверен: 261 тест, дымовой тест на живом счёте прошёл
на золоте (девять сценариев, 2 цента). Инструмент выбран — **XAU-USD**,
по глубине стакана внутри полосы награды.

**Бот ни разу не работал в боевом режиме.** Всё измеренное получено в теневом,
где заглушка принимает любую заявку.

Решение о запуске упирается в одно число: **фактическая ставка пула должна
превышать 22 USD за Maker Hour**. Она не публикуется и с нашей стороны
не вычислима — берётся из интерфейса биржи после первого дня работы.
Подробности и вывод порога — в §0 PLAN.md.

**Язык — только английский**, см. `.cursor/rules/english-only.mdc`. Правило
распространяется на всё, что программа выводит: ошибки, логи, вывод CLI,
сообщения валидации, имена тестов, — **и на комментарии в коде тоже**.

Существующие русские комментарии остаются как есть и не переводятся: правка ради
языка засоряет историю и не даёт ничего, кроме конфликтов при слиянии. Но всякий
новый комментарий пишется по-английски, включая комментарии в `config.yaml`
и `.env.example`. Кодовая база сходится к одному языку по мере того, как код
переписывается по существу.

## Архитектура

Гексагональная. Зависимости направлены строго внутрь:

```
cmd → app → ports ← adapters
        ↓
      domain          (не зависит ни от чего)
```

| Слой | Правило |
| --- | --- |
| `internal/domain` | Чистый. Ни I/O, ни `time.Now()`, ни сети, ни глобального состояния. Только stdlib и `decimal`. |
| `internal/ports` | Только объявления интерфейсов и DTO. Никакой логики. |
| `internal/app` | Оркестрация. Зависит от `ports` и `domain`, **никогда** от `adapters`. |
| `internal/adapters` | Реализации портов. Могут зависеть от `domain` для маппинга. |
| `cmd` | Композиционный корень. Единственное место, где адаптеры связываются с портами. |

Нарушение направления зависимостей — это баг, а не стилистическое замечание.

## Деньги и числа

- **`float64` для цен, количеств и денег запрещён.** Только `decimal.Decimal`
  (`internal/domain/money`).
- `float64` допустим ровно для двух вещей: пороги в базисных пунктах (`money.Bps`)
  и значения метрик. Цена ордера при этом всегда вычисляется в `decimal` и снэпается к тику.
- Любая цена, уходящая на биржу, проходит через `SymbolSpec.SnapPrice`, любое
  количество — через `SymbolSpec.SnapQty`.

## Событийная модель

- `internal/events` — типизированная синхронная in-process шина.
- **Контракт: обработчик не имеет права блокироваться.** Долгая работа — через
  собственную очередь подписчика (актор кладёт событие в свой inbox и возвращается).
- Синхронная доставка выбрана намеренно: тесты получаются детерминированными,
  скрытых горутин нет.
- Публикация только доменных фактов в прошедшем времени (`MarkPriceUpdated`,
  `OrderFilled`), не команд.

## Конкурентность

- Одна горутина-актор на символ владеет всем своим состоянием. Мьютексов в `app` нет.
- Общее изменяемое состояние между акторами запрещено — только сообщения.
- Ядро решения — чистая функция `Decide(State, Event) → (State, []Command)`.
  Ни времени, ни случайности внутри: всё приходит в событии.

## DI

- `uber-go/fx`. Модуль на пакет: `fx.Module("standx.rest", fx.Provide(...))`.
- Конструкторы принимают и возвращают **интерфейсы** из `ports`, не структуры адаптеров.
- Ресурсы с жизненным циклом (WS-соединения, HTTP-серверы, акторы) регистрируются
  через `fx.Lifecycle` с `OnStart`/`OnStop`. Никаких `go func()` в конструкторах.

## Время

- Никаких прямых `time.Now()`, `time.Sleep`, `time.After` вне адаптеров.
  Только порт `ports.Clock` — иначе тесты становятся медленными и флаки.

## Ошибки

- Оборачивать с контекстом: `fmt.Errorf("place order %s: %w", id, err)`.
- Сигнальные ошибки — через `errors.Is`/`errors.As`, не сравнением строк.
- В горячем пути ошибка не глотается: либо обработана, либо опубликована
  как событие, либо поднята в супервизор.

## Безопасность

- Приватные ключи только из переменных окружения, никогда из файлов конфигурации.
- Ключи и JWT не попадают в логи. Тип `Secret` с `String() → "[REDACTED]"`.
- Любой путь, отправляющий ордер, обязан проверять `runtime.mode == live`;
  в `dry_run` команда логируется и публикуется как событие, но не уходит на биржу.

## Тесты

- `internal/domain` — property-based (`pgregory.net/rapid`), инварианты из PLAN.md §7.1.
- `internal/adapters/fake` — симулятор StandX на том же проводном протоколе;
  интеграционные тесты гоняют бот без изменений против него.
- Тесты с реальными ордерами — build tag `live`, требуют `STANDX_LIVE=1`.
- Криптография (подписи) обязана иметь фиксированные тест-векторы.

## Конфигурация

Три слоя по возрастанию приоритета: **умолчания кода → `config.yaml` → окружение
`MMSTANDX_*`**. Это одна система, а не две.

- **`config.yaml`** — параметры стратегии: аппетит, оценщик волатильности,
  лимиты риска, параметры начисления. Версионируются, объясняются комментариями,
  **запекаются в Docker-образ**. Правка требует пересборки — намеренно:
  артефакт должен отвечать на вопрос «с какими порогами работал бот».
- **Окружение** — то, что различается между машинами и запусками: `MM_MODE`,
  `MM_SYMBOLS`, приватный ключ, **размер счёта и пределы риска**. Любой ключ
  конфигурации переопределяется (`MMSTANDX_RISK_MAXDAILYLOSSUSD=60`,
  `MMSTANDX_SYMBOLS_XAU-USD_ALLOCATIONUSD=1000`), поэтому срочная правка
  не требует сборки. Ключ содержит имя символа как есть, вместе с дефисом.

Значения в файле остаются политикой по умолчанию с объяснением, почему порог
именно такой; окружение задаёт то, что отличает конкретный счёт. Двух источников
истины это не создаёт, потому что **действующие значения спрашиваются
у работающего процесса**, а не выводятся из того, какой образ на сервере:

```bash
curl -s localhost:9090/metrics | grep mm_risk_limit
```

Убирать секцию `risk` из `config.yaml` ради «незапекания» бессмысленно:
при её отсутствии значения возьмутся из `internal/config/defaults.go`, то есть
из скомпилированного кода — запечены сильнее, а прочитать их на сервере уже
нельзя.
- **Секреты только из окружения.** Поле ключа помечено `koanf:"-"`; попытка
  задать его в YAML роняет загрузку.
- `runtime.symbols` (`MMSTANDX_RUNTIME_SYMBOLS=XAU-USD`) отбирает инструменты
  из описанных в файле. Неизвестное имя — ошибка со списком известных.

## Развёртывание

Образ собирается на машине разработки и уезжает в реестр вместе с конфигурацией.
На сервере ровно два файла: `docker-compose.yml` и `.env`.

```bash
make image && make push                      # машина разработки

mkdir -p data && chown 10001:10001 data      # сервер, один раз
docker compose pull && docker compose up -d
```

Каталог `data/` лежит рядом с `docker-compose.yml` — статистика забирается
обычным `scp`, без `docker cp`. Он обязан принадлежать пользователю контейнера
(uid 10001), иначе процесс не сможет писать и упадёт на старте.

Значения в `.env` **без кавычек**: `docker compose` их снимает,
а `docker run --env-file` передаёт дословно, и ключ кошелька перестаёт
разбираться.

`pull` обязателен: с тегом `:latest` один `up -d` поднимет уже скачанный образ.

**`config.yaml` не монтировать томом.** При отсутствии файла Docker создаёт
на его месте пустой каталог, и процесс падает на «is a directory» — только
на той машине, где файла нет, то есть в проде.

Сторожа в Docker нет: он обнаруживает лишь смерть процесса, а это закрывает
`restart` плюс сверка при старте. Вне Docker сторож нужен.

## Наблюдаемость

| Что нужно | Откуда | Объём |
| --- | --- | --- |
| Состояние сейчас | `curl localhost:9090/metrics` | — |
| Прямо сейчас | `data/stats/current.json` — незавершённый час, обновляется раз в 10 мин | — |
| История по часам | `data/stats/hourly-*.ndjson`, забирается `scp` | 110 КБ/сутки |
| Разбор инцидента | логи процесса, причины съёма с измеренными величинами | ~20 МБ/сутки |

Почасовая свёртка пишется процессом сама: мгновенные величины сворачиваются
в квантили, счётчики — в разность за час. Час выбран потому, что биржа считает
начисление по календарным часам UTC.

## Команды

```bash
make build      # сборка всех бинарников в ./bin
make test       # unit + property тесты
make test-live  # дымовой тест с реальными ордерами (нужен STANDX_LIVE=1)
make lint       # go vet + staticcheck
make image      # Docker-образ с запечённой конфигурацией
make push       # публикация образа в реестр
make record     # запуск cmd/recorder для сбора рыночных данных
```

`STANDX_LIVE=1` относится **только к дымовому тесту**. Боевой режим самого бота
включается единственной ручкой — `MM_MODE=live`.
