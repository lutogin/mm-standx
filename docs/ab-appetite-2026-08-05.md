# Парный эксперимент по аппетиту, 5 августа 2026

Два процесса на одном потоке данных, 10:48 → 00:01 CEST, **13.2 часа**,
ноль провалов, ноль ошибок. Инструменты: XAU-USD и BTC-USD.

| | A — strict | B — relaxed |
| --- | --- | --- |
| `jumpMultiple` | 1.25 | 1.0 |
| `floorMarginBps` | 1.5 | 0.5 |

Схема парная намеренно. Последовательное сравнение 4–5 августа оказалось
недействительным: у золота присутствие выросло вчетверо, а заливы упали, чего
ослабление аппетита при неизменном рынке дать не может — режим рынка перебил
эффект параметра. Здесь оба варианта видят один и тот же скачок с точностью
до последнего знака, поэтому расхождение объясняется параметром.

но за счёт неравномерности четыре часа всё же дали полный зачёт. Считать нужно
по часам.

## Экономика

Награда и стоимость линейны по нотионалу, поэтому точка безубыточности
**не зависит от размера депозита**. Стоимость залива — тейкер 4 bps + мейкер
1 bp + полспреда как проскальзывание, отнесённая к одной ступени из трёх.

| Инструмент | Вариант | Окупается при |
| --- | --- | --- |
| XAU-USD | strict | `$/MH > 31` |
| XAU-USD | relaxed | `$/MH > 194` |
| BTC-USD | strict | `$/MH > 71` |
| BTC-USD | relaxed | `$/MH > 151` |

Переход от строгого к ослабленному оправдан только при `$/MH > 266` на золоте
и `$/MH > 368` на биткойне.

**Строгий аппетит на золоте — самая дешёвая точка входа из четырёх.** Он даёт
5.5 зачётных часа из 15 при четырёх заливах за все 13 часов и окупается уже
при 31 долларе за Maker Hour.

## Оговорки

1. **Теневой залив — верхняя оценка.** Считается касание рынком цены ступени,
   а не факт исполнения: очередь в стакане нам не видна, и наш ордер там
   последний. Реальная частота ниже, насколько — покажет только боевой прогон.
2. **Стоимость считана по полному объёму ступени.** Частичное исполнение
   дешевле. Обе оговорки смещают оценку в одну сторону: настоящие пороги
   `$/MH` **ниже** приведённых, то есть реальность выгоднее расчёта.
3. **Один день, один режим.** 13 часов покрывают европейский полдень
   и американскую сессию. Азиатская и выходные не покрыты.
4. **BTC в варианте B упёрся в `minBps: 5.5`** — сравнивается не два аппетита,
   а аппетит против пола.

## Вывод

Из четырёх конфигураций разумны две, и обе на золоте. Биткойн проигрывает ему
на любом уровне `$/MH`: при равном ослаблении даёт вдвое меньше зачётных часов
и вдвое чаще заливается, потому что его полоса награды уже съедена
волатильностью, а не спредом.

Следующий вход — `$/MH` из интерфейса биржи. Он один разделяет три исхода:
ниже 31 — не работает ничего, между 31 и 266 — золото со строгим аппетитом,
выше 266 — золото с ослабленным.

## Как снимать статистику на сервере

Три способа, по возрастанию удобства для разных задач.

**Прямо сейчас, одним числом** — реестр в памяти отвечает по HTTP:

```bash
ssh server 'curl -s localhost:9090/metrics' | grep -E '^mm_(quote_uptime|kill_switch|fills)'
```

**История по часам** — процесс пишет её сам, внешний сборщик не нужен:

```bash
scp server:~/mm-standx/data/stats/hourly-*.ndjson .
```

Около 110 КБ в сутки. Сколько часов взяли полный зачёт по золоту:

```bash
jq -r 'select(.metric=="mm_quote_uptime_ratio" and .labels.symbol=="XAU-USD")
       | "\(.hour[11:13]) \(.p50)"' hourly-*.ndjson
```

**Разбор инцидента** — полный лог с причинами и измеренными величинами
(`logs/*.ndjson`, порядка 20 МБ в сутки на два инструмента). Нужен, когда
почасовой свёртки не хватает и требуется восстановить последовательность
событий.
